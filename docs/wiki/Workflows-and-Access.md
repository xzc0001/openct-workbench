# 检查与权限工作流

## 重建流程

导入目录、DICOM 文件或 ZIP 后，服务校验格式和像素，按序列归组并检查空间
几何。确认有效序列、结构与模式后开始计算；预览随着已完成结构逐步更新。
失败、取消或服务重启时，输入和已有结果按工作流保留，不能把失败当作成功。

源影像与派生体积、掩膜、网格、HTML 分开保存。检查备注可以包含敏感信息，
请由内部管理规范约束；不要在 Issue 或截图中泄露备注。

## 角色与检查授权

| 身份 | 默认可见范围 | 管理边界 |
| --- | --- | --- |
| 管理员 | 全部检查 | 账号、授权、访客链接、节点设置与系统管理 |
| 上传用户 | 自己上传的检查 | 按所有权管理和继续处理自己的检查 |
| 只读用户 | 被明确授权的检查 | 可查看；不可下载、重建或修改 |
| 访客 | 当前链接指定的检查 | 受有效期约束的只读浏览 |

检查所有者或管理员可向只读账号授权，撤销后对应查看权限失效。
账号管理与密码修改入口仅管理员使用；普通账号需向管理员申请密码变更。
角色隐藏按钮之外，后端也检查权限。

## 访客链接

管理员选择检查后创建链接，默认 7 天，可配置 1–365 天，并可随时撤销。
入口把令牌交给服务后清除地址片段，后续通过受限会话访问。
链接本身是敏感访问凭据，只能发给授权接收人。只读并不能阻止截图、
浏览器提取已展示数据或其他屏幕记录方式。

使用真实数据前应独立验证未登录、越权、撤销、过期和跨检查访问行为。
